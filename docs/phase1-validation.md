# Phase 1 pipeline validation

The implementation smoke run on 2026-10-04 used all eight workloads, trace seeds
1 and 2, 2,000 requests per trace, 100 catalogue keys, capacity fractions 0.01,
0.05 and 0.1, and all 16 policies including Clache ablations. It produced 768 result
rows and 384 summary rows, each combining both seeds. This verifies the pipeline;
it is not the full 10-million-request, five-seed research matrix or a performance
claim.

A separate mixed trace with 200,000 requests, 1,000 catalogue keys and seed 7 was
regenerated byte-identically. Replaying it with `--jobs 1` and `--jobs 8` produced
identical results excluding wall-time columns, and byte-identical sampled decision
logs, for all 16 policies. Reversing the report input order preserved both tables.

Reproduce against a build containing the real engine, every policy, trace I/O,
configuration parser, trace generator and simulator:

```sh
python3 tests/integration/test_phase1_pipeline.py \
  --bin-dir build/release/apps \
  --report-script benchmarks/scripts/report.py \
  --work-dir build/phase1-validation
```

The script preserves CSVs, binary traces, sidecars, decision logs, report Markdown,
summary CSV, and `validation.json`. Optional plots can be generated by rerunning
`report.py` on the sixteen `<workload>-seed<N>.csv` files with matplotlib available.
Do not include the separate determinism outputs in that report invocation.

The simulator's complete dependency snapshot passed 122 C++ tests and six Python
CLI integration tests in each of Debug, Release and UBSan. Tracegen passed 51 C++
tests and two Python CLI tests in each configuration. Report validation passed 16
Python tests. `run_matrix.sh` also completed a real smoke run with two workloads,
two seeds and three capacities, including environment capture and reporting.

No Git branches were merged to assemble these local validation inputs. The
simulator snapshot was created from `origin/feat/clache-policy` at `555d134`, then
overlaid with the owned files from configuration `6b4f909`, trace I/O `bb1d0c1`,
classic policies `3ad5fc6`, modern policies `aed62e6`, reports `406313b`, and simulator
`2d7c44b`. Tracegen binary came from `380d1db`. Temporary test stubs were absent;
actual estimator and metadata implementations supplied the symbols. Snapshot
builds report Git SHA `unknown`; the commits here identify the assembled sources.

See [simulator.md](simulator.md) for upstream engine limitations and accounting
conventions. GitHub CI is a separate gate: policy PRs currently require the real
estimator/metadata dependencies on the umbrella branch, and corresponding test
stubs must be removed there. Local validation does not mean those PR checks pass.
